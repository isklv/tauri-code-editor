# Code Editor

Редактор кода на **Tauri v2 + Monaco Editor + xterm.js**: дерево файлов, вкладки,
подсветка синтаксиса и настоящий терминал с PTY.

## Архитектура

```
┌─────────────────────────────────────────────┐
│                  WebView                    │
│   Monaco Editor  ·  xterm.js  ·  Explorer   │
└───────────────────┬─────────────────────────┘
                    │ IPC (invoke / events)
┌───────────────────▼─────────────────────────┐
│               Rust backend                  │
│  list_dir / read_file_text / write_file_text│
│  create_entry / rename_entry / delete_entry │
│  pty_start / pty_write / pty_resize / kill  │
│         portable-pty → /bin/sh, bash…       │
└─────────────────────────────────────────────┘
```

Фронтенд общается с бэкендом только через команды Tauri (`src/api.js`), поэтому
вне Tauri (`npm run dev` в браузере) он автоматически переключается на
демо-режим с файлами в памяти — удобно для работы над UI.

## Требования

- **Node.js** 20+
- **Rust** 1.80+ (через rustup)
- Linux: `webkit2gtk-4.1`, `gtk3`, `libappindicator`, `librsvg2` — см.
  [tauri.app/start/prerequisites](https://tauri.app/start/prerequisites/)

## Запуск

```bash
npm install
npm run tauri:dev     # десктопное приложение
npm run tauri:build   # сборка дистрибутива
```

Только фронтенд, без Rust (демо-режим в браузере):

```bash
npm run dev           # http://localhost:1420
```

## Сборка в GitHub Actions

Два workflow в `.github/workflows/`:

| Workflow | Когда | Что делает |
| --- | --- | --- |
| `ci.yml` | push в `main`, PR | `cargo fmt --check`, `cargo clippy -D warnings`, `cargo test`, сборка `.deb` |
| `android.yml` | push в `main`, PR, теги `v*`, вручную | Собирает APK и кладёт его в артефакты сборки |

### Где взять APK

**Релиз `latest`** — самый простой путь. Каждая зелёная сборка `main`
обновляет prerelease с прямой ссылкой на APK: страницу можно открыть прямо
на телефоне и нажать на файл. Артефакты вкладки Actions для этого не годятся —
они отдаются в виде `.zip` и требуют входа в GitHub.

По тегу `v*` APK дополнительно прикрепляется к обычному релизу.

Артефакт прогона называется `code-editor-apk`, а если секреты подписи не
настроены — `code-editor-apk-unsigned`.

### Почему без подписи не установится

**Неподписанный APK Android не устанавливает вообще.** Установщик показывает
`App not installed`, не объясняя причину, а `apksigner verify` на таком файле
отвечает `DOES NOT VERIFY: Missing META-INF/MANIFEST.MF` — сертификата в пакете
нет совсем.

Поэтому релиз `latest` публикуется только для подписанных сборок: выкладывать
APK, который заведомо не ставится, хуже, чем не выкладывать ничего. Что именно
собралось, workflow пишет в сводку прогона.

### Секреты для подписи

Без секретов workflow отработает, но APK выйдет **неподписанным** (в лог
попадёт предупреждение) — это нужно, чтобы PR из форков не падали. Обратите
внимание: Gradle в этом случае называет файл `app-universal-release-unsigned.apk`,
а не `app-universal-release.apk`.

Чтобы CI подписывал релизы тем же ключом, что и локальная сборка, добавьте
четыре секрета в **Settings → Secrets and variables → Actions**:

`ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`,
`ANDROID_KEY_PASSWORD`.

Значения печатает скрипт — запустите его сами и скопируйте вывод:

```bash
./scripts/github-secrets.sh
```

Вывод содержит приватный ключ подписи, поэтому не вставляйте его никуда,
кроме формы секретов GitHub. Сам workflow удаляет `keystore.properties` и
расшифрованный keystore сразу после сборки, а в лог секреты не попадают —
они передаются через переменные окружения, а не через командную строку.

## Тесты

```bash
cd src-tauri && cargo test
```

Покрывают чтение/запись файлов, сортировку и защиту от бинарных файлов, а также

## Горячие клавиши

| Клавиши | Действие |
| --- | --- |
| `Ctrl+P` | Быстрое открытие файла |
| `Ctrl+S` | Сохранить файл |
| `Ctrl+N` | Создать файл или папку |
| `Ctrl+W` | Закрыть вкладку |
| `Ctrl+Tab` / `Ctrl+Shift+Tab` | Следующая / предыдущая вкладка |
| `Ctrl+B` | Показать/скрыть проводник |
| `` Ctrl+` `` | Показать/скрыть терминал |

В терминале `Ctrl+S`, `Ctrl+W`, `Ctrl+P` и `Ctrl+N` отдаются шеллу — это его
штатные привязки (XOFF, kill-word, история). Приложению остаются только
`` Ctrl+` ``, `Ctrl+B` и `Ctrl+Tab`.

Правый клик по файлу или папке в проводнике открывает контекстное меню
(на сенсорном экране — долгое нажатие).

## Android

SDK уже установлен в `~/Android/Sdk`, переменные окружения прописаны в `~/.bashrc`:

| Компонент | Версия / путь |
| --- | --- |
| JDK | 21 (`/usr/lib/jvm/java-21-openjdk`) |
| SDK Platform | android-36 |
| Build-Tools | 36.1.0 |
| NDK | 27.3.13750724 |
| Rust-таргеты | `aarch64-linux-android`, `armv7-linux-androideabi`, `i686-linux-android`, `x86_64-linux-android` |

```bash
npm run android:build       # подписанный release-APK под arm64 (~11 МБ)
npm run android:build:all   # все ABI
npm run android:dev         # запуск на подключённом устройстве с hot-reload
```

APK появляется в
`src-tauri/gen/android/app/build/outputs/apk/universal/release/app-universal-release.apk`.

Установка на телефон:

```bash
adb install -r src-tauri/gen/android/app/build/outputs/apk/universal/release/app-universal-release.apk
```

### Подпись

Release-сборка подписывается ключом из `~/.android/code-editor-release.jks`;
пароли лежат в `src-tauri/gen/android/keystore.properties` (в git не попадает).
Без этого файла сборка просто выйдет неподписанной — Gradle-конфиг это учитывает.
**Ключ нельзя терять:** Android не даст обновить установленное приложение
APK, подписанным другим ключом.

### Доступ к файлам

Редактору нужен доступ ко всему хранилищу, поэтому в манифесте объявлен
`MANAGE_EXTERNAL_STORAGE`. Это «специальное» разрешение: обычный диалог его не
выдаёт, поэтому при первом запуске приложение один раз открывает нужный экран
настроек. Если отказаться, редактор продолжит работать — проводник откроется в
приватной папке приложения, а сменить корень можно кнопкой **Open Folder**.

На Android системный выбор папки возвращает `content://`-URI, который
`std::fs` не умеет открывать, поэтому там **Open Folder** показывает
собственный список корней (`Home`, `Documents`, `Downloads`, `App storage`,
`/`) плюс поле для ручного ввода пути. Кнопка `↑` поднимает проводник на
уровень выше.

### Интерфейс на телефоне

- Проводник — выдвижная панель (кнопка `☰`), закрывается после открытия файла.
- Увеличенные тач-зоны для дерева, вкладок и кнопок.
- Учитываются вырезы и системные панели (`env(safe-area-inset-*)`), потому что
  Tauri включает edge-to-edge.
- Под терминалом — ряд клавиш, которых нет на экранной клавиатуре: `Esc`,
  `Tab`, `Ctrl` (залипающий), стрелки, `^C`, `|`, `~`, `/`, `-`.

Автономное Linux-окружение (Alpine Linux + PRoot) ставится автоматически при
первом запуске: приложение скачивает PRoot и minirootfs (~7 МБ), настраивает
репозитории `apk` и выполняет `apk update && apk add git`. После этого терминал
сам переключается на Alpine, и в нём работают `apk add go`, `apk add rust cargo`
и прочие пакеты — без root-прав и сторонних программ. Пока окружение не готово
(или если оно не поставилось), терминал работает на `/system/bin/sh`.

Переключатель в шапке терминала выбирает оболочку — Alpine или системную — и
содержит пункт «Переустановить Linux» на случай, если окружение сломалось.
Если Alpine-оболочка не стартует, приложение сообщает об этом в строке
состояния и откатывается на системную, а не делает вид, что всё в порядке.

### Samsung DeX

DeX — это тот же APK в оконном режиме на мониторе, с мышью и клавиатурой.
Что сделано специально под него:

**Манифест.** `resizeableActivity="true"` и `<layout>` с размерами окна по
умолчанию (1100×720dp, минимум 420×320dp). В `configChanges` добавлены
`density`, `navigation`, `touchscreen` и `fontScale` — без них DeX пересоздаёт
активити при стыковке с монитором и при смене размера окна, то есть редактор
перезапускался бы с потерей открытых вкладок. `keep_process_alive` от Samsung
сохраняет процесс при переносе окна между экраном телефона и монитором.
`android.hardware.touchscreen` и `freeform_window_management` объявлены как
необязательные — иначе система считает приложение пригодным только для
сенсорного ввода.

**Интерфейс.** Крупные тач-зоны включаются по `(hover: none) and
(pointer: coarse)`, а не просто по `pointer: coarse`: в DeX подключена мышь,
поэтому там остаётся компактная десктопная плотность. Ряд экранных клавиш под
терминалом по той же причине скрыт, но его можно включить кнопкой `⌨` —
на случай работы без физической клавиатуры.

**Изменение размера окна.** Окно в DeX тянут мышью в любой момент, поэтому
высота терминала и ширина проводника пересчитываются на каждый `resize`:
редактору всегда остаётся минимум 120px, миникарта включается только при
ширине больше 900px. Проверено на переходах 1600×900 → 640×420 → 1920×1080 —
горизонтальной прокрутки не возникает, панели возвращаются в норму.

**Клавиатура и мышь.** Добавлены `Ctrl+P` (быстрое открытие с нечётким
поиском по относительному пути: `smjs` → `src/main.js`), `Ctrl+Tab` для
переключения вкладок, `Ctrl+N`, и контекстное меню по правому клику. Поиск
пропускает `node_modules`, `.git`, `target`, `build` и подобные каталоги и
ограничен 60 000 просмотренных записей и 200 результатами.

Кнопка `☰` видна при любой ширине окна: иначе, свернув проводник в узком окне
и растянув окно обратно, его нельзя было бы вернуть мышью.

### Не проверено

Эмулятор не запускается в этом окружении (podman-контейнер, `qemu-system-x86_64`
падает в SIGSEGV независимо от KVM и выбранного GPU-бэкенда), физического
устройства тоже нет. Поэтому APK собран и подписан, но **на живом Android и в
DeX не запускался**.

Поведение интерфейса проверено в headless Chromium в двух конфигурациях:
телефон (412×915, touch, `hover: none`) и DeX-подобная (1600×900, Android UA,
мышь) — включая палитру, контекстное меню, `Ctrl+Tab` и серию изменений
размера окна. Манифест проверен распаковкой готового APK: флаги
`resizeableActivity`, `<layout>` и биты `configChanges` на месте.

Что остаётся неизвестным до проверки на устройстве: работает ли PTY через
`/dev/ptmx` под SELinux, доходят ли `Ctrl`-сочетания до WebView в DeX, и как
Monaco ведёт себя с экранной клавиатурой. Для проверки подключите телефон с
включённой отладкой по USB и выполните `adb install -r ...` — логи смотреть
через `adb logcat | grep -i tauri`.
